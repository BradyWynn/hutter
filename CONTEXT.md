- **CRITICAL DOUBLE-COUNTING RULE (`S1 + S2`):**
  Official Hutter Prize scores $S = S_1 (\text{comp.exe}) + S_2 (\text{archive.exe})$. Because offline GPU-trained weights ship inside **both** `comp.exe` and `archive.exe`, **every `1 MB` of offline weights costs `2 MB` (`RATE_MULT = 2.0` in `ecqat.py`)**:
  $$\text{hutter\_s12\_mb} = \text{Payload MB} + 2 \times \text{Weight MB} + 2 \times \text{Vocab MB} + \text{Extra Meta MB} + 0.10$$
  *(Preprocessed metadata like `enwik9.prep.meta.lzma` is generated by `comp.exe` at compression time, so it ships only once in `S2`.)*

## 2. Metrics & Evaluation Protocol

Always evaluate on **`EVAL_WINDOWS=2048`**, **`T=2048`**, **`stride=1024`** (`eval_hutter.py`, `train.py`, `ecqat.py`):
- **`hutter_s12_mb` (`S1 + S2`):** Primary Goal B objective (`2×` offline weights).
- **`hutter_mb` (`S2` / LTCB):** Secondary metric (`1×` weights, comparable to LTCB `archive9` column).
- **`ema_strided_bpb` / `q_strided_bpb`:** Always normalized per original `1,000,000,000`-byte `enwik9` while scaling payload accurately by `n_bytes_stream = os.path.getsize(base_stream)` (critical when `DATA=enwik9.prep.split4096` where `n_bytes_stream = 871,170,809` B!).
- **Never lower `EVAL_WINDOWS` below `2048`:** Even `1024` windows shifted apparent `enwik9` payload by `~1.15 MB` due to local entropy variance (dense prose vs. US Census tables).

## 4. Empirical Findings & Ablation Ledger

### What Worked (Keep)
1. **Full-file `split4096` BPE (`bpe_tok.py`):** `349.8M` toks on raw `enwik9`; `301.5M` toks (`2.890 B/tok`, `11.5 KB` vocab) on `enwik9.prep`.
2. **`matchfeat v2` (`pool_8w24_hyb1`, 0 archive bytes, 0 extra params, ~5.5 min 1-core CPU):**
   - Lifted 6-col oracle coverage on raw `enwik9` from `~45% → 65.28%` (`61.21%` on cleaner `enwik9.prep`).
   - **20k `v10-moe17m` ablation (`wrzeq245`):** **`111.17 → 108.80 MB` (`-2.37 MB` net win!)**.
   - *Key insight:* Independent per-`k` active-cont/multi-way collapsed all 6 cols onto the same match (`UNION` *dropped* `45.4% → 44.7%`). Deduplicated pooling into `(longest, most-recent, top-4 distinct)` was the breakthrough.
3. **ECQAT v2.1 (`mix2` + `rowcol` + per-tensor entropy + `SCALE_BITS=8`):**
   - Per-tensor entropy coding saves `-0.08 to -0.14 MB` strictly free (including `~3 KB` rANS table overhead).
   - `SCALE_BITS=8` (`uint8` per-tensor log-scales + `zlib-9`) saves `-0.15 MB` net (`0.38 → 0.17 MB` scales, only `+0.06 MB` payload).
   - `LR_W=8e-4` over `35k` steps beat `3e-4` over `20k` steps by `-0.37 MB` on `E=16` (`101.80 → 101.43 → 101.29 MB` w/ `SCALE_BITS=8`).
   - On raw `enwik9` `E=16` (`100k` BF16 `t99gev0u` = **`89.08 MB` BF16 payload**), reached **`101.29 MB` `S2` (best LTCB!)** (`91.38 MB` payload + `9.84 MB` wt, `exp 2.38 bpw`, `37.1%` zeros; `111.18 MB` `S1+S2`). Self-distilled `KD_ALPHA=0.5` (`dlxq5bkh`) hit `101.34 MB` `S2` / `110.84 MB` `S1+S2` (`9.44 MB` wt, `exp 2.27 bpw`, `41.4%` zeros).
4. **Looped MoE (`L=6, n_loop=3` = `14` passes, `12.91M` params) + `RATE_MULT=2.0` (`S1 + S2` breakthrough!):**
   - Trading our huge spare single-core CPU budget (~40h unused!) for weight bytes crushed unlooped `L=8×1` (`16.85M`) on `enwik9.prep` at 20k + 10k ECQAT@2×:
     - `P1` (`L=8×1`, `16.85M`, `bleysz64`): `99.05 + 3.12` + `4.93` wt → `S2 = 107.16 MB`, **`S1+S2 = 112.16 MB`**.
     - **`P2` (`L=6×3`, `12.91M`, `14` passes, `cw1gee8r`):** `98.72 + 3.12` + **`4.26 MB` wt** (`emb 3.78, blk 3.04, exp 2.26 bpw`, `38.2%` zeros) → `S2 = 106.16 MB` (`-1.00 MB`), **`S1+S2 = 110.48 MB` (`-1.68 MB` vs `P1` — ALREADY beat our 100k `E=16` `S1+S2` of `110.84 MB` in just 20k steps!!)**.

### What We Tested & Ruled Out (Do NOT Repeat Without Addressing Root Cause)

| Experiment | Result | Why It Lost |
|---|---|---|
| `nosplit4096` / `split8192` (on 6M v9) | `+3.35` / `+0.43 MB` worse | Misaligned matches (`nosplit`) or emb cost (`split8192`). |
| Bolted-on online n-gram hash (`online_hash_bench.py`) | `-0.30 MB` max | Overlaps with 6-col `matchfeat`; hurts calibration at higher LRs. |
| Naive semantic page reordering (`reorder_enwik9.py`) | `+0.45 MB` net | Scrambled `<id>` tags (`~0.5 MB`) + `0.50 MB` perm. *(Re-testable only after XML metadata separation!)* |
| Learned N-Gram `Engram` (`+8.45M`) | `+2.82 MB` worse | `0.30 MB/MB` vs `1.5+ MB/MB` for MoE experts. |
| Uniform Proximal-L1 QAT (`L1_EXPERT=0.010`) | `+2.70 MB` worse | Lost `3.11 MB` payload per `1 MB` weight saved; ECQAT beat it by `3.66 MB`. |
| **Walsh-Hadamard pre-rotation (`WHT=1` in `ecqat.py`)** | `+0.01 MB` dead heat (`107.17` vs `107.16 MB`) | Muon-trained weights already have near-Gaussian kurtosis (`3.36`); WHT slightly reduced zero-sparsity. Keep `WHT=0`. |
| **Extending context `T=2048 → 4096`** | Only **`-0.115 MB`** pure context gain (zero-variance paired test on exact 6.02M target bytes) | `matchfeat v2` already handles long-range exact copying, and 6/8 layers are `SWA=256`. Keep **`T=2048`**. |
| **Chunk-level online TTT (`ttt_bench.py`, `stride=512`)** | `-0.008 MB` best (`coda_full`), `+0.01` to `+0.95 MB` worse on `head`/`adarms`/`dense_all`/`all` | Static MDL weights + `matchfeat v2` + `T=2048` attention already capture local adaptation; single-chunk (`B=1`) Adam steps add article-boundary variance. |
| **Compressing `<comment>`/`<contributor>` with plain `lzma` (`prep_enwik9.py` v1)** | Broke even on BF16 payload+meta (`100.00` vs `99.60 MB` raw at 20k) | `lzma` spent `1.33 MB` on English `<comment>`s + `0.65 MB` on `<contributor>`s and broke mutual information with article bodies. Fix in `prep v2`! |
